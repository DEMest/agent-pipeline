# Соглашения проекта

Файл ведёт агент. Он читает его перед каждой задачей и дописывает сюда решения,
принятые по ходу работы.

Смысл файла — пережить конец сессии. Решение, оставшееся только в переписке,
через две недели забудется, и следующая задача будет сделана вопреки ему.

Что сюда попадает: выбор между равноценными вариантами и причина выбора. Чего здесь
быть не должно: команды проверок (они в `.pipeline/config.yml`), пересказ структуры
кода (её видно в коде) и решения, отменённые позже — такие строки удаляются, а не
копятся с пометкой «устарело».
