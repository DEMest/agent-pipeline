# Отчёт по задаче 2: Генератор `scripts/pipeline.sh`

## Реализовано

✓ Модуль `src/generate-sh.mjs` с функцией `generatePipelineSh(config, hash) -> string`
✓ Полный набор из 7 тестов в `tests/generate-sh.test.mjs`
✓ Коммит: `1b3515e feat: генерация scripts/pipeline.sh из конфига`

## Функциональность

Функция `generatePipelineSh()` генерирует полнофункциональный sh-скрипт на основе объекта конфига:

- **Заголовок:** шебанг `#!/usr/bin/env sh` и маркер хеша конфига
- **Функции:** для каждого ключа в `config.checks` создаётся функция `check_NAME()` с командой
- **Диспетчер:** case-statement принимает имя проверки или `all` для запуска всех
- **Обработка ошибок:** неизвестный аргумент выводит справку и завершается с кодом 2
- **Настройки оболочки:** `set -eu` для прерывания при ошибке команды
- **Кодировка:** только LF-переводы строк (без CR/CRLF)
- **Порядок:** проверки выводятся в порядке ключей конфига

# Исправление дефекта: Reserved имя `all` в проверках

## Проблема

Генератор `src/generate-sh.mjs` строит POSIX-конструкцию `case` с веткой на каждую проверку плюс агрегатную ветку `all)`. Валидатор `src/config.mjs` разрешал имена проверок по регулярному выражению `^[a-z][a-z0-9_]*$`, которое допускало имя `all`.

Если проверка называлась `all`, в сгенерированном скрипте появлялись две ветки `all)`. POSIX `case` выполняет только первую совпавшую, поэтому скрипт молча выполнял одну проверку `all` и пропускал все остальные, включая обязательные.

## Решение

Запретить `all` как имя проверки в валидаторе. Ошибка возникает при загрузке конфига, а не в проде.

## Что изменено

1. **`src/config.mjs`**
   - Добавлена константа `RESERVED_CHECK_NAMES = ['all']`
   - Добавлен комментарий о том, что имена проверок становятся именами функций sh
   - Добавлена валидация в `parseConfig`: проверка имени против зарезервированных имён с выбросом `ConfigError` с `field === 'checks'`

2. **`tests/config.test.mjs`**
   - Добавлен тест: отвержение проверки с именем `all` с правильным `field === 'checks'`

3. **`tests/generate-sh.test.mjs`**
   - Добавлен регрессионный тест: инвариант, что ветка `all)` встречается ровно один раз

# Удаление дефектного теста-пустышки

## Проблема

Тест `'диспетчер all) встречается ровно один раз'` в файле `tests/generate-sh.test.mjs` был неработающий по двум независимым причинам:

1. `String.prototype.match()` без флага `/g` возвращает результат с максимум одним элементом совпадения. Проверка `matches.length === 1` всегда истинна независимо от реального количества вхождений `all)` в тексте.
2. Объект `CFG`, используемый в тестовом наборе, не содержит проверку с именем `all`, поэтому проблемный путь кода в генераторе никогда не выполняется.

Тест был добавлен по ошибочному указанию при предыдущем исправлении.

## Решение

Удалён весь тест из `tests/generate-sh.test.mjs` целиком. Замена не требуется, так как валидация защиты от имени `all` находится в валидаторе конфига (`src/config.mjs`) и уже покрыта настоящим тестом в `tests/config.test.mjs` с проверкой на отвержение имени `all` при `field === 'checks'`.
